# Security Policy

Open UI is a desktop application that processes local project files, imported assets, generated code, AI responses, and optional network requests. Security boundaries are part of the product architecture, not an add-on.

## Supported versions

Open UI is currently pre-alpha. Until the first stable release, only the latest development revision is supported for security fixes.

## Reporting a vulnerability

Do not disclose exploitable vulnerabilities in a public issue. Use GitHub's private vulnerability reporting/security advisory feature for this repository when available. Include the affected version/commit, reproduction steps, impact, and any suggested mitigation. Do not include real API keys, personal files, or other people's data in a report.

## Security requirements

- The Tauri webview must not expose arbitrary shell/process execution.
- Native commands must be explicit, minimal, typed and input-validated.
- File-system access must be scoped to user-selected/project-owned locations.
- Canonical paths must be checked to prevent traversal and symlink escape.
- Imported HTML/SVG and rich content must be treated as untrusted and sanitized.
- Generated preview code must run inside an isolated preview boundary and must not inherit privileged native APIs.
- AI output is untrusted input and must be schema validated before application.
- Online AI is opt-in and must visibly indicate network use.
- Offline mode must prevent optional AI/provider traffic rather than merely hiding UI controls.
- API keys/tokens must never be stored in `.openui` project documents, exported source, telemetry, or normal logs.
- Secrets should use an OS-backed credential facility when available.
- Logs must redact credentials and sensitive request headers.
- External URLs must be validated before opening.
- Dependencies must be pinned/locked and audited in CI.
- Release artifacts should be reproducibly generated by CI and code-signed when signing infrastructure is available.
- Update metadata and installers must be authenticated before automatic update support is enabled.

## AI trust boundary

Prompts, model output, downloaded models, remote responses and generated source code are not trusted. AI cannot directly invoke privileged native commands. The editor converts AI output into a constrained document-operation format, validates it, shows the resulting change, and keeps it undoable.

## Privacy

Core editing is local-first. Open UI must not require telemetry for operation. Any future diagnostics/telemetry feature must be documented, opt-in where required, minimize collected data, and never collect project source or API credentials by default.
